# 源缓存、状态与失败退避

应用层 `ProviderStorage` 管理目录缓存和源状态；共享 media 客户端仍只负责协议请求与解析。
配置仍存于原命名空间，缓存文件位于应用私有 cacheDir/provider-metadata-v1，不包含视频流字节。

- 启动/浏览先加载已有 M3U、VOD 页面快照，目录可立即浏览，然后按时效决定是否请求网络。
- M3U 与 VOD 页面新鲜期十分钟；影片详情五分钟。过期内容可在网络失败或退避期间作为旧快照展示，最多保留七天。
- 缓存键包含源 ID、接口地址、查询词/页码或影片 ID。更换地址不复用旧地址缓存，也不沿用旧地址退避状态。
- 成功响应更新最后响应/成功时间及耗时；失败保存失败类型、连续次数和下次重试时刻。
- 连续失败的退避为 15s、30s、60s、120s……最多十分钟；退避不会自行发起请求，只在下次需要这个源时检查。
- 手动「测试」和影视「刷新/重试失败源」会绕过退避。用户取消请求不计作源失败。
- 有旧快照时，失败仍可展示内容，同时保留失败状态；不会把读取缓存伪装为一次新的网络成功。
- 设置源卡片显示状态、最后响应时间、耗时、已缓存标识；失败时显示退避时刻。
- 只缓存元数据，普通目录单项不超过 8 MB（XMLTV 节目单上限 32 MB），总量最多 48 MB / 128 项，按最近写入淘汰。写入失败不丢弃已经成功取得的新响应。
- 翻页按源单独推进：已完成响应的源不必等待其他慢源；新的刷新会取消之前一整组目录请求。

这不是持续健康监控。源状态表示最近一次实际请求，播放线路的延迟/速度指示是另一套按当前选集进行的小样本探测。

## 设置中的缓存管理

「常规」提供两个独立入口，进入时异步统计磁盘占用，清理完成后重新统计，并显示成功或失败结果：

- **清除数据缓存**：删除 `provider-metadata-v1`（M3U、影视分类/分页/详情、XMLTV）和 `danmaku-v1`（五分钟弹幕窗口），同时清空共享弹幕仓库的分集内存缓存。清除源状态中的 `cachedAt`，保留实际请求状态与失败退避。清理前已发出的数据请求可以返回内容，但不能重新写入缓存。
- **清除图片缓存**：通过界面使用的同一个 Coil 默认单例 ImageLoader 清除磁盘和内存缓存。封面和台标使用默认缓存策略，大小由 Coil 根据设备空间管理；设置显示的数值只计磁盘占用，不包含已解码位图内存。

弹幕窗口有效期七天，单项最多 4 MB，总量最多 32 MB / 96 项；分集列表仅缓存在内存中，最多 32 项。

清理不会删除 SharedPreferences 中的源配置、收藏、播放记录和弹幕偏好，也不清空当前界面已加载的目录/节目单、当前弹幕渲染状态或播放器缓冲。Media3/MPV 未配置应用级视频磁盘缓存；播放资源探测另有短期内存缓存。浏览、播放及进行中的图片请求可能再次生成缓存，因此清理后的磁盘占用可能很快增加。
