# OhMyTV 弹幕移植

已移入 SeleneTV 的六个平台适配器及轻量渲染引擎，并接入 VOD 播放。

## 使用方式

播放影片后按 OK 呼出控制条，上键进入倍速胶囊，左键可到「弹幕」开关和「弹幕设置」。
首次默认关闭；打开后各平台分别匹配当前影片与分集，并发合并弹幕，单个平台慢或失败不阻塞其他平台。
设置抽屉分为「弹幕样式」「弹幕来源」：样式只包含区域、透明度、字号、速度、密度和防重叠。
来源标题只作分组，不获取焦点。组内每行直接显示「影片名 · 分集」候选，OK 一次完成影片和分集选择；
再次 OK 停用已选行。同组单选，不同来源可以同时启用。已选行左/右键每次提前/延后 1 秒，
左右键不会将焦点移出该行。默认显示当前集候选和已选项，其余分集可在原组内展开，不跳转匹配页面。
打开设置时视频和弹幕同时冻结，不启用循环预览；样式变化只重绘静止画面。关闭时只恢复原本正在播放的视频。

## 模块边界

- media/danmaku：统一协议模型、可取消 suspend 客户端；六个平台的私有协议适配器留在 internal 包。
- app/domain/danmaku：规范影片/分集与弹幕的匹配，不把播放器线路 URL 当作弹幕身份。
- app/data/danmaku：候选查询、当前/下一 300 秒窗口、七天非空磁盘缓存（最多 96 项 / 32 MB）。
- app/playback/danmaku：纯 Kotlin 布局引擎、TextureView 与后台硬件 Canvas 渲染。
- app/ui/danmaku：播放状态协调和设置面板。

同一集切播放资源不重新匹配弹幕；缺集不回退第一集，无法精确匹配时要求手动选择。
HTTP 请求、解压和窗口大小有上限，退出或切集会取消请求。无数据时不持续进行 60 Hz 绘制。
默认半屏、50% 密度；限制活跃对象数量，保留防重叠以适配低内存电视。

org.json 只用于内部平台协议解码：JVM 库使用标准依赖，Android 消费方排除此重复依赖，使用系统实现。
不引入 Rhino、旧弹幕服务器、AppDataService 或 SeleneTV 播放页面状态。

## 验证范围

协议/引擎移植测试、平台匹配、缓存退避、显式开启、缺集处理和电视硬件 Canvas 绘制均有测试。
本轮在开发机以「甄嬛传」联网验证，B 站、腾讯、优酷和乐视返回了弹幕；爱奇艺样例为空，芒果未搜到。
这是特定网络和样例的结果，不代表六个平台对所有影片一直可用。弹幕缺失不影响视频播放。

## 多源合并与持久化

每个平台独立维护影片候选、已选影片、分集、加载状态、错误及当前/下一 300 秒窗口。
网络并发最多 3 个，失败窗口退避 30 秒；大幅跳转进度会取消过时窗口请求。
关闭一个来源立即从合并结果移除，再启用可复用窗口，不刷新其他来源。

偏移保存在应用层，按规范影片、分集和平台隔离；影片内的新分集可继承该平台的影片默认值，
单集已经调整过则保留其覆盖值。不同影片不继承新调整值。旧全局偏移迁移为历史默认值。
手动影片与分集绑定分别保留来源作用域；旧单源绑定只恢复到原平台，不套用其他平台的分集 ID。

原始缓存始终保留平台原始时间；合并时加上各自偏移，播放器直接使用视频时间，避免重复偏移。
同模式、规范化文本相同、相距不超过 1 秒的跨平台弹幕合并；同平台重复和不同模式保留。
合并在后台执行并合并快速按键更新，保留播放位置前 15 秒到后 600 秒，单源候选最多 12000 条、
最终最多 24000 条；原有密度和活跃对象上限继续生效。自动影片和分集匹配要求唯一候选，歧义留给用户确认。
